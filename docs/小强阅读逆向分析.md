# 小强阅读（NovelReader）逆向分析报告

分析对象：`D:\Program Files (x86)\小强阅读\`
分析时间：本软件立项阶段
分析目的：确定对标能力边界，为「书源阅读器」的设计决策提供依据

---

## 一、总体结论

**小强阅读是一款 Windows 原生 C++ 桌面小说阅读器**，具备「搜索 → 加书架 → 下载全本 → 导出 TXT」的完整闭环，
但其书源体系是**自研的、写死在数据库里的固定规则体系**，不具备导入第三方书源的能力。

| 维度 | 小强阅读 | 书源阅读器（本软件） |
|------|----------|----------------------|
| 平台 | Windows 原生 C++ | Electron（Node.js） |
| HTTP | 自研 | Node `http/https` + keepAlive 连接池 |
| HTML 解析 | libxml2 | cheerio（css-select） |
| 编码转换 | iconv | iconv-lite |
| 书源格式 | **自研 SQLite 规则表**（`SiteV6` / `EngineSite`） | **Legado 3.x 书源 JSON** |
| 自定义书源 | ✗ 无 | ✓ 导入/导出/在线库 + 可读性探测 |
| 本地存储 | SQLite（`NRDBV6` / `NREngine`） | JSON 落盘（镜像其 `chm/` 目录结构） |
| 阅读界面 | 内嵌浏览器 + jQuery | Electron 渲染进程 |
| 导出 TXT | ✓ 内建 | ✓ 单文件/分章/分卷 + 编码可选 |

### 依赖分析

`iconv.dll` + `libxml2.dll` + `zlib1.dll` 三件套说明：
- HTTP 抓回来的 HTML 交给 **libxml2** 解析（而不是用内嵌浏览器的 DOM）→ 规则引擎在 C++ 侧基于 XPath/CSS 求值
- **iconv** 负责 GBK/UTF-8 互转（中文小说站大量使用 GBK）
- **zlib** 处理 gzip/压缩

`model/*.html` + `jquery-1.10.0.min.js` 说明：**下载完成后的阅读**用的是内嵌 IE/WebView 渲染本地 HTML，
而不是原生绘制——因为这两个模板里有 `chapter(N)` 这样的 JS 跳转函数。

## 四、自研规则语法（逆向所得）

这是本报告最有价值的部分。小强阅读的规则语法与 Legado **完全不同**：

### 4.1 `##` = 正则捕获（**与 Legado 相反**）

```
# 小强阅读：整条规则就是一个正则，第一个捕获组即结果
##<td class="odd"><a href="(.*?)">.*?</a></td>     → 取 href
##<td class="odd">([^<]*)</td>                     → 取作者

# Legado：## 是挂在规则尾部的替换后缀
a@href##正则##替换                                  → 先取 href，再做替换
```

### 4.2 CSS / 标签选择器（两套并存）

```
class.b_algo                     → CSS 类选择器
title.下一页@href                → 按 title/文本内容选中，再取 href
tag.h2@tag.a.>1                  → tag 选择器 + `@` 链 + `.>1` 取第 1 个（> 后为下标）
tag.h3@tag.a@href                → 取 a 的 href
```

`tag.a.>1` 里的 `>N` 是**下标**（注意不是 CSS 的子元素选择器 `>`）。

### 4.3 URL 模板

```
https://cn.bing.com/search?q={searchkey}|char=utf-8
                          ↑ 占位符        ↑ 目标编码（用 |char= 指定）
```

`|char=utf-8` 是**管道分隔的编码声明**——因为中文站常见 GBK，必须两边都声明。

### 4.4 `#` 前缀 = 正则，且**不含 `##`**

配置表里的模板规则使用单 `#` 前缀：

```
[StoryListRegex]
#<\s*td[^>]*>\s*<\s*a[^>]*href\s*=\s*['|"][^>]*?['|"][^>]*>[^>]*<
#<\s*dd[^>]*>\s*<\s*a[^>]*href\s*=\s*['|"][^>]*?['|"][^>]*>[^>]*<

[StoryContentRegex]
#<div[^>]*class="content">(.*?)</div>
#<dd[^>]*id="content">(.*?)</dd>
#>([^>]*<\s*br[^<>]*>.*?)<\s*/\s*div\s*>
```

`['|"]` 这种写法（把 `|` 也放进字符类）是**不严谨的**——`|` 本不该被当引号，但能工作。

### 4.5 目录/搜索页的自动识别

```
[StoryListExpressions]
//td/a[@href]
//dd/a[@href]
//li/a[@href]
//div/a[@href]
//span/a[@href]

[StoryListRegexName]     → 逐条尝试，取第一个匹配到的作为「书名」
[StoryListRegexUrl]      → 同理取「章节 URL」
[StorySearchListRegex]   → 用「目录 / 列表 / 全文阅读」等锚文本找详情页入口
```

这是一套**兜底启发式**：书源没配规则时，用这 5 种 XPath + 5 种正则逐个试探。
`MinChapterNum = 100` 是「多少章以上才算有效目录」的阈值。

## 六、章节缓存格式（`chm/` 目录）—— 本软件直接对标

```
chm/
└─ <32位大写MD5>/                    每本书一个目录，共 102 个
   ├─ list.json      220,511 B       目录元数据（JSON 数组）
   ├─ list.txt       130,002 B       内嵌浏览器用的 HTML 目录片段（GBK）
   └─ <32位MD5>.txt  2,400–3,800 B   每章一个文件，共 43 个（本书）
```

### 6.1 `list.json` — 结构（实测）

```json
[
  {
    "ChapterIndex": 1,
    "ChapterName": "完本感言",
    "ChapterURL": "https://www.haitang43.com/read/58723/21985984.html",
    "HaveRead": 0,
    "SiteURL": "www.haitang43.com",
    "StoryAuthor": "",
    "StoryName": "神秀之主"
  },
  { "ChapterIndex": 2, "ChapterName": "第972章 大结局 (ωoо1⒏ υip)", ... }
]
```
该书共 **986 章**，`ChapterIndex` 从 1 连续编号，`HaveRead` 记阅读标记。

### 6.2 `list.txt` — 内嵌浏览器的目录 HTML

GBK 编码，**单行无换行**：
```html
<dd><a id="chapter_0" href="#" onclick="javascript:chapter(0)" title="完本感言">完本感言</a></dd>
<dd><a id="chapter_1" href="#" onclick="javascript:chapter(1)" title="第972章 大结局 (ωoо1⒏ υip)">第972章 大结局 (ωoо1⒏ υip)</a></dd>
...
```
`chapter(N)` 是 `chapterlist.html` 里定义的 JS 函数，点击后由内嵌浏览器加载对应的
`<MD5>.txt` 并在同一窗口渲染正文。**这就是「章节文件名叫 32 位 MD5」的原因**——文件名是
章节 URL 的 MD5，`chapter(N)` 用 `list.json[N].ChapterURL` 的 MD5 去找文件。

### 6.3 章节正文文件

GBK 编码，HTML 片段（不是纯文本）：
```html
  &emsp;&emsp;神秀之上。<br/>&emsp;&emsp;一家金色楼船划过天际，向着下方投下沉重的阴影。<br/>
  &emsp;&emsp;船身上符文闪烁，散发着阵阵威压，带着一方小山的重。<br/>
  ...
```
- 用 `&emsp;&emsp;` 做段首缩进（两个全角空格）
- 用 `<br/>` 换行
- 原生保留 HTML → 阅读时由内嵌浏览器渲染，**导出 TXT 时需要再做一次标签剥离**

### 6.4 `filter/通用方案` — 内容净化

GBK 编码，`[filter]` 段，格式为 `被替换词=替换为`（分号后是注释）：
```
[filter]
陆6=登陆				;插件：陆6 替换为 登陆
未登6=				;插件：未登6 替换为 
药Xing=药品
xiangdao=想到
Yin荡=淫荡
...
```

`filter.dat`（21 B）是一个指针：
```
[filter]
通用方案=
```
即「启用名为『通用方案』的过滤器」。

## 七、`log.txt` 揭示的运行流程

GBK 编码，5,627 B。关键行：

```
MCNovelReaderDB::GetBookInfo        → 数据库读取
MCReaderWnd::ReadBook               → 开始阅读
MCNovelReaderWnd::OpenTabItem       → 打开标签页
ClickBookShlefItem                  → 点击书架条目（原文拼写错误：Shlef）
nextpage                            → 翻页
www.xqushuba.com列表页打开失败，链接：https://www.xqushuba.com/shu13542/
笔趣阁内容页下载失败，链接：javascript:void(0);
新笔趣阁内容页下载失败，链接：javascript:a_info();
小说下载成功，开始导出
```

**结论**：
1. `log.txt` 里出现的小说站域名（`www.xqushuba.com`、`笔趣阁`、`新笔趣阁`）在 `EngineSite` 表里**找不到** →
   证实站点规则**硬编码在 exe 里**
2. `链接：javascript:void(0);` / `javascript:a_info();` 说明目录页里混有 JS 伪链接，程序盲目把它们当章节 URL 去下载 → 失败
3. `小说下载成功，开始导出` 证实 **TXT 导出是内建功能**（对应 `Config.ExportFolder=D:\BOOK`）

| 阅读进度（`ReadChapterIndex` / `VScrollBarPos`） | `data/books/<bookId>/progress.json` |
| 内容净化（`filter/通用方案`） | `src/engine/source.js` 的 `cleanContent()` |
| TXT 导出（`ExportFolder`） | `src/export/txt.js`（单文件/分章/分卷 + 编码/换行/目录可选） |
| 编码识别（iconv.dll） | `src/util/encoding.js`（GBK 假 utf-8 回退 gb18030） |

### 8.2 改进点（本软件的差异）

| 问题 | 小强阅读 | 本软件 |
|------|---------|--------|
| 书源封闭 | 自研 SQLite 表，无法导入第三方 | **Legado 3.x JSON**，可导入 yck2026.fun 社区书源 |
| 无自定义能力 | 用户只能改数据库里的 `SiteV6`（46 列） | 图形界面导入/导出/编辑 + **可读性探测** |
| 死了就死了 | 站点改版 → 规则失效 → 用户无法自救 | YCK 社区持续更新，一键安装 |
| 无准入校验 | 直接添加，坏了才知道 | **4 阶段探测**：不能读取的网站不允许添加 |
| 盲目下载 | 把 `javascript:void(0);` 当 URL 下载（`log.txt` 实证） | 探测阶段即拒绝，且 `isBadUrl()` 过滤伪链接 |
| 导出单一 | 只有一种 TXT 格式 | 3 种布局 × 2 种编码 × 可选目录/书头 |

### 8.3 关键差异：规则语法不可复用

**小强阅读的规则语法与 Legado 不兼容**：
- 小强：`##正则` 捕获、`title.文本@属性`、`tag.a.>N` 下标、`{searchkey}|char=utf-8`
- Legado：`选择器@属性##正则##替换`、`class.x.0@tag.a.list`、`{{key}}`

因此本软件**不移植小强阅读的规则引擎**，而是重新实现 Legado 3.x 引擎
（`src/rules/rule.js` + `src/rules/jsrt.js`），因为：
1. Legado 有成熟的社区书源生态（yck2026.fun 上持续更新）
2. 交付点②③ 明确要求使用该站书源 + 支持自定义书源
3. 复刻小强的封闭语法等于复刻其死路

**小强阅读唯一值得继承的是「数据组织方式」**：目录 JSON + 每章一个文件 + 进度记录，
本软件以 `data/books/<bookId>/` 结构镜像之（见 8.1 表）。
